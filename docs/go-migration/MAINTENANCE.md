## PHP → Go 的选择性同步

1. 先核对已发布 PHP 的固定 SHA、当前私库状态和未提交内容，保留用户工作。
2. 审查 PHP 产品差异，区分共享前端/Worker/bridge、统一合同、平台实现及部署说明；不把 merge 成功当行为迁移完成。
3. 前端产品代码沿用已审查 PHP main，不为 Go 增加平台特判；后端保留 unified-v1、稳定 ID、服务端默认选择、完整候选和用户显式选择语义。
4. 只移植适用于当前 Go 已实现能力的产品行为与回归。公共 main 的后续提交按差异选择性接收，保留来源 SHA 与选择理由；不默认全量合并每次上游变化。
5. 新增 PHP 版本基线必须由对应 PHP 产品路径、固定输入和时钟生成。旧原始输入、期望、生产器及哈希不改；不变样本可引用旧基线，但记录来源和核对结果。
6. 分开记录新增失败、既有失败、通过与未验证项。URL fragment 和超范围 `size_bytes` 旧合同冲突不因迁入私库消失，不删除场景、不放宽前端或独立验证。

私库建立与离线同步阶段没有迁移其余平台。当前按维护者的继续开发指令推进 B 站；不扩展四项能力白名单、DASH/合流执行器或小红书 4K 新传输方案，不部署 Go、不变更现有 PHP 生产。PR #11 自动恢复的真实浏览器待验收项单独保留。
