## 产品变化

失败或中断的、当前页面拥有完整选择快照的单文件任务，可在下载卡片详情
点击 **刷新链接并重试**。普通“重试”保持旧行为。不会把所有 403 当作过期，
不会自动刷新、后台循环重试，也不会在页面恢复后仅凭旧 URL 重建媒体身份。

一次点击最多调用一次既有 `resolveItem`，使用原有 30 秒准备期限和取消机制。
只接受原 item ID/类型、variant ID、source ID 对应的完整文件；原选择消失、
响应不匹配、仍然过期/不可用或交付类型变化时明确失败，不借新的 default。
未确认旧 Worker 已结束时不能启动刷新：继续使用原 forget acknowledgement、
原尝试匹配与并发操作锁。重复点击、清除和取消不生成第二次下载。

刷新准备阶段清除过时地址、旧交付 ID 和本机来源上下文，不暴露旧“打开源链接”。
成功后使用新响应中**对应来源自己的** URL、size_bytes 及已证实的格式信息，
原始查询字节不重写。任务仍保留旧选择，界面中的服务器结果和用户当前选择
不会被异步刷新结果改写。普通传输阶段的既有有界同版本来源回退策略未改。

本轮只对 ready file、具有来源 ID 和 resolve_url 的本机任务提供新入口。
Live/ZIP/分片、无 ID 来源、已移交浏览器/结果未知/已取消或已完成的任务，
不伪造刷新能力。刷新不提供断点续传；是确认旧尝试结束后的一个新尝试。
Worker、bridge、后端、Schema、PHP 基线、原十项公共差异和依赖锁未修改。

### 中间失败及仍未完成的测试清理

首次三个 Worker 确认测试持有更新前的任务对象，和 Pinia 的替换语义不符，
因此轮询不到终态；改为查询当前行，保留原确认、并发及身份断言后通过。
前端无依赖升级，Browserslist 提示只记录，不修改锁文件。

额外使用 PHP 8.3.6 动态执行旧 `unified-review-identity.php --export` 试验时，
新消费测试只有 2/4 通过。该动态 CDN tape **不声明大小**，最初新模拟传输
错误地产生空文件；已改为与既有测试相同的四字节合成载荷。新增测试末尾
仍将已接收字节与可能缺省的 `size_bytes` 作相等断言，因此这个额外 PHP
动态入口还不能宣称通过；它不同于既有冻结 PHP/实际 Go 的完整流水线。

修正该新增断言的工具编辑被安全检查阻止，相关编辑已停止，未换工具绕过；
也没有删除用例、改冻结预期或从测试选择器排除失败场景。追加机器报告的
新四项计数断言同样受阻，当前仅已把四项接入原门禁选择器；最终需核对日志
确实执行四项，不能把旧续签计数当作这四项的结果。

## 父版本与备用来源集合耦合：仍未修复

源码核对确认：头条/皮皮虾通过来源集合形成内部表示分组，而公共
`FileVariants` 在没有 `private_media_identity` 时用排序后的 source ID
集合生成公开 variant ID。新增备用来源会改变该集合；纯重排不会。

现有提供的复现输入没有独立的上游文件/表示标识；work/item ID 仅标识作品，
无法单独区分其不同编码、音轨和文件。“第一条 URL”“最小 source ID”、
分辨率/时长/大小或在前端跨 variant 查找旧来源，都没有被采用为替代方案。
没有改后端 ID、缓存跨请求猜测关系、泛化删除 query 或改动旧 oracle。

所以，对这类刷新后父 variant 改名的响应，新恢复入口仍会安全失败，
**不能声称恢复已覆盖这项缺口**。该问题需独立可靠的媒体表示依据或明确
审查过的合同变更；不要以本轮第二项修复和全绿回归关闭它。
