## 必须保持的合同

- 沿用 unified-v1、`items → variants → delivery`、服务端 `default`、默认与显式选择的续签，以及稳定 item/variant/resource/source 身份。简单单文件响应保持简洁，前端只读取后端默认。
- 字段对拍包括缺失/null/false/0/空数组、精确大整数、错误码和 HTTP 状态、顺序、实际流规格、媒体与来源关联。不能只比较字段集合或成功数量。
- 沿用现有普通/debug 候选策略；覆盖过滤与四项能力保护只有公共层一份实现。四项闭合类别为高帧率、确认的 HDR 类型、已证明的备选语言、多声道，不新增保护类别或平台私有默认排序。
- 前端产品、下载 Worker、bridge 与 schema 保持现有合同。允许扩展测试生产器以让原前端消费实际 Go 输出，不能通过修改前端适配 Go 差异。
- 生产 Go 不调用 PHP。固定 PHP 只用于独立基线生成；Go 不能生成自己的 expected。旧输入、期望、生产器和哈希不得覆盖。已批准的 10 项公共投影差异继续精确消费，不扩宽白名单。
- 普通页面/API、媒体探测、微博转发分别保留适当预算。入口授权、逐跳主机/DNS/公网地址校验、连接绑定、TLS、取消与读取限额不能因迁移或传输接口而失效。
- 不实现 DASH/合流执行器，不新增小红书 TLS 指纹传输或宣称 4K 端到端专项完成。已有上游媒体和已验证原画能力须如实保留，不以统一 deferred 掩盖降级。

## 每个平台的验收门槛

1. 从固定 PHP 产品路径执行固定输入、请求带与时钟，记录运行时、来源文件哈希、完整请求序列、legacy wire 和普通/debug 公开响应。可复用 B 站的离线 producer 机制，不能只复用手写 formatter 测试。
2. 实现真实 Go parser/adapter 并接入正式 API/CLI 注册；对 PHP 输出逐字段比较。失败、空结果、备用来源、特殊媒体和身份续签必须覆盖。兼容差异必须有理由与证据，新增语义争议先报告，不能修改期望消除失败。
3. 将实际 Go 输出交给既有独立 Schema＋语义验证器与未修改的前端消费者；检查 default、显式选择、快照与续签。微博另验二进制协议、流式取消与资源释放。
4. 运行对应平台和公共层的有意义回归，最终里程碑执行全包 Go 测试、race、vet、构建、格式、来源/入库清单、完整独立与前端门禁。修复失败后重跑受影响检查；没有剩余风险时停止重复验证。
5. 更新本表、平台说明、`acceptance.md`、机器报告及 Draft PR：写明实际 Head、运行链接、已验证层次、失败和待验收，不把历史记录算作本轮执行。

固定 PHP 8.3.6 的已验证运行环境为官方镜像 digest `php@sha256:9ed77294c3332080ebcd2f6b9a2d390565eaa4a05fc26aefff62aa9b0af9b5e9`（linux/amd64）。现有 workflow 在无网络、只读挂载中重放 PHP，再与入库 oracle 逐字节比较。继续复用固定运行时断言，不将 8.3.36 等替代版本认作相同证据。

## 真实平台与交付门槛

离线对拍证明受控输入的迁移一致性，不能代替真实平台可用性、浏览器保存或生产部署。具备获准环境和有效链接时，对同一批正常解析结果进行 PHP/Go 对照，保留来源、时间和有效期，检查实际最高可用画质。复用足够的既有证据；没有必要时不下载完整媒体，不重复大文件测速、不改本机网络，也不访问生产进行排障。

真实来源过期、反爬、网络或凭据阻断时，保留原证据并明确标为待验收，不据此归因版本回归，不循环换源试到成功。可以继续独立的离线开发。全部代码和离线门禁通过时只可报告“九平台实现与离线验收完成”；真实平台门槛未满足时不能报告“整体迁移验收完成”或“可切生产”。

合并与部署仍须另外授权。切换前必须冻结最终 PHP 基线并入库，准备含 Caddy/FPM 配置及前端产物的旧发布包，密钥只记录引用，并演练一次回滚；参见 [rollback.md](rollback.md)。

## 每轮自动接续方式

1. 读取实际远端 PR、分支 Head、本文件和最新验收记录，确认仍在本任务仓库/分支。保护已有未提交工作；不要把临时工作区的本地快照 SHA 当作远端提交。
2. 有未完成的实现/审查/CI 时接着完成；否则选表中下一个平台。每轮实际推进产品代码、基线或验证，不只发计划与提醒。可并行分配不同平台文件，公共注册、合同、CI 和最终提交由一个集成者负责。
3. 重要进展写入仓库并提交。更新 ref 时校验刚读取的远端 Head，禁止 force push；有并发提交先读差异并整合。不要另开第二个对同一分支写入的自动任务。
4. 若当前环境缺少 Go/PHP，使用既有 GitHub Actions 固定运行环境。宿主网络失败不循环重试、不改变代理；通过已授权 GitHub 工具读取/提交/查询 CI。源文件可从远端重建，临时本地目录不是持久检查点。
5. 新文件必须登记 `public-files.json` 并生成 `.gitignore`，通过清单检查后发布。禁止把 Cookie、真实密钥、用户私有输入或下载媒体写进公开仓库/日志。
6. 仅在平台里程碑、具体阻断或最终交付时给维护者摘要。任务记录具体 Head、测试、未完成项和下一步，不把“已触发 CI”写成“CI 通过”。

发生新的授权/连接/凭据要求时按工具要求停止相关操作并明确说明来源，不绕过限制。仅一个平台受阻时继续其他平台；全部剩余工作受阻时暂停自动任务、报告一次所需条件。同一原因连续两轮没有新证据或进展时，停止重复尝试并升级为具体阻断。全部实现和可执行验收结束后暂停自动任务，提交最终汇总与真实待验收清单，避免永久空转。用户要求暂停或改变边界时立即遵从。
