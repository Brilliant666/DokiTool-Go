## 已复现的产品缺陷

`getDownloadTarget` 对只含 `variant_id` 的画质选择读取该版本的第一个来源。
原 `snapshotItem` 只保存这个不完整选择；若当前来源过期，异步 resolve 后
会再次读取新的第一个来源。来源重排会静默换源；原来源消失也可能下载
另一个来源并记为完成。单来源默认引用省略 `source_id` 时同样受影响。

四个回归场景在基线产品代码上均失败：

| 初始选择 | 续签后变化 | 正确结果 |
| --- | --- | --- |
| 只选版本 | 原来源保留但不再是第一项 | 按原来源 ID 使用续签后的 URL |
| 只选版本 | 原来源消失，仅剩另一来源 | 明确失败，不发媒体请求 |
| 单来源 default 省略来源引用 | 原来源保留但不再是第一项 | 按原来源 ID 使用续签后的 URL |
| 单来源 default 省略来源引用 | 原来源消失，仅剩另一来源 | 明确失败，不发媒体请求 |

## 最小修复

仅在创建下载任务快照时，把当前已经确定的完整文件来源 ID 固化到任务内。
即使该来源已过期，仍在 resolve 之前固定它，而不是从新响应的排序或新默认值猜选。
已有显式来源 ID 保持原样；未解析条目和 pair 等交付类型沿用原逻辑。
仅对原来源本身有 ID 的情况补齐引用，不生成新公开 ID，不做 URL 等价猜测。

UI 的原始选择单独保留为 `selectionKey`，不因任务固化而改写页面选择、
服务端 default 或展示中的响应。成功续签后读取新来源自己的大小与格式；
不会把原来源旧长度或另一来源长度套给新地址。既有有界传输失败后的
同版本线路回退规则不变；这里修复的是 resolve 阶段的来源身份重新解释。

后端身份算法、公开 Schema、PHP 输入/expected/producer/hash、原十项公共差异
和 Worker 均未修改。没有给头条/皮皮虾添加未经证据证明的 query 删除规则。

## 尚待处理

历史在线差异需按以下类别继续审查，不凭汇总扩展身份规范化：
A：同来源仅凭据/有效期变化；B：同媒体版本但实际 CDN 来源变化；
C：不同媒体/编码/音轨/资源；D：证据不足。
只有 A 类的已证实动态字段才可能进入局部身份规则。B/C/D 类不能静默
借新 default、同分辨率或相邻条目完成原任务。缺少 ID 的来源仍不能被本次
修复宣称为具备跨调用稳定身份；需后续独立证据或明确拒绝策略。
Live 整体保存、其他平台稳定性、生产包和回滚演练仍独立保留。
